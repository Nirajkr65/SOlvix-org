The project has two main parts:

frontend/
  React application used by users and admins.

backend/
  Express API server that handles authentication, problems, submissions, AI chat, notes, discussions, profiles, and admin operations.

Basic request flow:

User performs action in React
-> Frontend calls backend using Axios
-> Express route receives request
-> Middleware verifies user if needed
-> Controller performs logic
-> MongoDB stores or fetches data
-> External APIs may be called
-> Backend sends response
-> React updates the UI

10. AUTHENTICATION FLOW
-----------------------

Registration flow:

1. User enters name, email, and password.
2. Frontend validates data using Zod.
3. Frontend sends POST /user/register.
4. Backend validates data again.
5. Password is hashed using bcrypt.
6. User is stored in MongoDB.
7. JWT token is generated.
8. Token is sent in a cookie.
9. Frontend stores user in Redux.
10. User is redirected to problems page.

Login flow:

1. User enters email and password.
2. Backend checks if user exists.
3. bcrypt compares password.
4. JWT token is generated.
5. Cookie is sent to frontend.
6. User becomes authenticated.

Why bcrypt?
  It securely hashes passwords, so actual passwords are never stored.

Why JWT?
  It helps verify authenticated users without storing session data in the database.

Why cookies?
  Cookies allow the backend to send and receive the token automatically with requests.

13. HOW CODE EXECUTION WORKS USING JUDGE0
-----------------------------------------

Judge0 is used for safe code execution.

Flow:

1. User writes code in Monaco Editor.
2. User clicks Run or Submit.
3. Frontend sends code, language, and problem id to backend.
4. Backend fetches test cases from MongoDB.
5. Backend maps language to Judge0 language id.
6. Backend sends source code, input, expected output, and language id to Judge0.
7. Judge0 returns execution tokens.
8. Backend polls Judge0 using those tokens.
9. Judge0 returns output, status, runtime, memory, and errors.
10. Backend sends final result to frontend.

Run:
  Uses visible test cases and does not save final accepted result.

Submit:
  Uses hidden test cases and stores submission result in MongoDB.

Supported languages:

- C++
- Java
- JavaScript


14. AI ASSISTANT FLOW
---------------------

The AI assistant uses Google Gemini.

When user asks a doubt:

1. Frontend sends user message and current problem context.
2. Backend sends that context to Gemini.
3. Context includes:
   - Problem title
   - Problem description
   - Test cases
   - Starter code

   - Chat history
4. Gemini returns a hint, explanation, debugging help, or solution guidance.

Important point:
  The AI is instructed to stay focused only on DSA and the current coding problem.

23. CURRENT REDIS ISSUE EXPLANATION
-----------------------------------

During checking, MongoDB connected successfully.

Redis failed with this type of error:

getaddrinfo ENOTFOUND redis-16805.crce292.ap-south-1-2.ec2.cloud.redislabs.com

Meaning:
  The Redis host could not be found.

Most likely reason:
  The old Redis Cloud database was deleted, suspended, renamed, or its endpoint changed after 3 to 4 months of inactivity.

Impact:
  Redis is mainly used for logout token blocklisting.

Fix:
  Create a new Redis database and update:

- REDIS_HOST
- REDIS_PORT
- REDIS_PD

Temporary improvement:
  Backend was changed so it can still start when Redis is unavailable. Auth and signup can work as long as MongoDB is connected.

26. SHORT 2-MINUTE SCRIPT
-------------------------

SOLVIX is a full-stack AI-powered coding practice platform. The goal of this project is to provide students with a complete environment for learning DSA. Users can register, log in, browse problems, solve them in a Monaco code editor, run code against sample test cases, submit code against hidden test cases, and track their progress.

The frontend is built using React, Vite, Redux Toolkit, Tailwind CSS, React Hook Form, Zod, and Monaco Editor. The backend is built using Node.js, Express.js, MongoDB, Mongoose, JWT, bcrypt, and Redis.

For code execution, I integrated Judge0. When the user clicks Run or Submit, the backend sends code and test cases to Judge0, receives execution results, and sends them back to the frontend.

I also integrated Google Gemini as an AI assistant. The AI gets the current problem context, so it can provide hints, debugging help, approaches, and complexity analysis.

The project also includes notes, discussions, community solutions, editorials, profile statistics, activity heatmap, and an admin panel for managing problems and videos.

Overall, SOLVIX is not just a coding judge. It is a complete learning platform that combines coding practice, AI guidance, revision, collaboration, and progress tracking.
